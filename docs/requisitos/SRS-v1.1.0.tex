\section{Introducci\'on}
\subsection{Prop\'osito}
Este documento especifica los requisitos funcionales y no funcionales del sistema SGROAS v1.1.0. Sirve como fuente \'unica de verdad para la matriz de trazabilidad, las pruebas automatizadas y la evidencia emp\'irica.
\subsection{Alcance}
SGROAS es un sistema web para centralizar la gesti\'on de recursos operativos, administrativos y de seguridad de cooperativas de transporte urbano en Ecuador.

\textbf{Alcance implementado en v1.1.0:} autenticaci\'on completa (login, refresh, logout con revocaci\'on, verificaci\'on de correo, recuperaci\'on de contrase\~na), control de acceso por rol (RBAC: ADMIN, COORDINADOR, SEGURIDAD), CRUD completo del m\'odulo funcional (conductores, usuarios, rutas, veh\'iculos, asignaciones, incidentes), subsistema ABD (programaciones, unidades, rutas ABD, incidentes ABD, alertas, cat\'alogos, reportes ABD), cach\'e Redis, procedimientos almacenados y funciones SQL, auditor\'ia mediante triggers, y respaldo con pg\_dump.

\textbf{Alcance excluido de este SRS:} m\'odulos de facturaci\'on y pagos.

\section{Descripci\'on global}
\subsection{Perspectiva del producto}
SGROAS es un sistema nuevo que reemplaza procesos manuales por una plataforma web centralizada.
\subsection{Funciones del producto (resumen)}
Autenticaci\'on completa; RBAC (ADMIN, COORDINADOR, SEGURIDAD); CRUD funcional; subsistema ABD; reportes por SP/FN; cach\'e Redis con TTL; auditor\'ia por triggers; respaldo pg\_dump \verb|--format=custom| diario con retenci\'on de 30 d\'ias; errores ProblemDetails (RFC 7807).
\subsection{Caracter\'isticas de los usuarios}
Administrador (total), Coordinador (operativo, sin usuarios ni ABD ni configuraci\'on), Seguridad (consulta).
\subsection{Restricciones}
Esquema por migraciones Flyway (prohibido \verb|ddl-auto=update|). No-CRUD elemental como SP/FN en \verb|db/procs/|. Prohibida concatenaci\'on de entrada de usuario en SQL/JPQL/HQL. TLS v1.3 en producci\'on; HTTP plano en local.
\subsection{Supuestos y dependencias}
Docker Desktop y Java 21. Credenciales semilla (\verb|admin@sgroas.com| / \verb|admin123|) exclusivas del entorno local (en \verb|db/seed.sql| y README), inexistentes en producci\'on. Mediciones seg\'un Makefile.

\section{Requisitos espec\'ificos}
\subsection{Vocabulario de estados de verificaci\'on}
\textbf{Verificado:} la evidencia confirma el cumplimiento y es reproducible. \textbf{Parcialmente verificado:} se cumple solo bajo condiciones declaradas (ej: entorno local). \textbf{Pendiente:} especificado pero no implementado o no verificado.
\subsection{Vocabulario de m\'etodos de verificaci\'on}
\textbf{test} (prueba automatizada), \textbf{demonstration} (curl/Postman/navegador), \textbf{analysis} (revisi\'on est\'atica), \textbf{inspection} (verificaci\'on visual de archivos/estructuras).
\subsection{Matriz de permisos por rol y operaci\'on}
Login/Refresh/Logout: los 3 roles. CRUD conductores/rutas/veh\'iculos: ADMIN+COORDINADOR (lectura Seguridad). CRUD usuarios: solo ADMIN (\verb|SecurityConfig| exige \verb|ROLE_ADMIN| en \verb|/api/usuarios/**|). CRUD asignaciones: ADMIN+COORDINADOR. CRUD incidentes: los 3 (Seguridad lectura+registro). Reportes: ADMIN+COORDINADOR (lectura Seguridad). ABD y configuraci\'on: solo ADMIN.
